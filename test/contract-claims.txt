# Contract claim registry
#
# A machine-checked index of *load-bearing* claims made by the normative
# contracts under docs/contracts/. Each record tethers one verbatim quote from
# a contract to one executable check, so a rule the implementation does not
# actually honor fails a gate instead of diverging silently.
#
# Run through `zig build test` (or `zig build test-contract-claims`):
#
#   bash scripts/test-contract-claims.sh            # enforce every record
#   bash scripts/test-contract-claims.sh --audit    # which contracts are unguarded?
#
# Record format (one blank line between records). Field values are read by
# stripping the literal key prefix, so a value may contain `:`, `|`, backticks,
# and markdown links without escaping:
#
#   claim id:  <stable dotted id>
#   contract:  <path, relative to the repository root>
#   section:   <verbatim heading text in that contract>   (optional, verified)
#   status:    enforced | known-divergence                (required)
#   issue:     <#n or URL>                                (required for known-divergence)
#   quote:     <verbatim span from the contract>          (required, verified)
#   check:     <check function name in test/contract-claims.checks.sh>
#              or script:<path> to reuse an existing gate verbatim
#
# Two rules make the registry self-defending:
#
#   * `quote` and `section` must still appear verbatim in the named contract
#     after whitespace normalization. If someone edits the prose, the record
#     fails as **prose drift** and must be re-tethered deliberately.
#   * Every check must pass. For `status: known-divergence` a passing check
#     means the divergence *still reproduces*; when the fix lands the check
#     fails and the record must be flipped to `enforced`. Neither direction
#     can rot quietly.
#
# Add a record when a contract states a rule the implementation must honor and
# no existing gate executes it. Do not record aspirational or unimplemented
# behavior as `enforced` — use `known-divergence` with an issue link.
