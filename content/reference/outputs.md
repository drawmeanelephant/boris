# Outputs & Artifacts

Boris produces several output formats. This page specifies the structure and schema of each artifact.

---

## HTML Site

```bash
./zig-out/bin/boris --html-dir dist
```

Output directory structure:

```text
dist/
  index.html
  getting-started.html
  guides/
    overview.html
    building-pages.html
  assets/
    theme.css           # copied from theme assets/
  _boris/
    search/
      search-index.json # generated by the search indexer tool
```

- Each page is a standalone HTML file at the path derived from its entity id.
- The `assets/` folder is copied from your theme's `assets/` directory.
- Navigation, breadcrumbs, and TOC are embedded in each page via layout markers.
- The `_boris/search/` directory is written by the standalone search indexer, not by the HTML compiler itself.

## Search Index

```bash
zig build --build-file tools/search-index/build.zig run -- \
  --root=./dist --out=./dist/_boris/search
```

File: `dist/_boris/search/search-index.json`

Schema (version 1):

```json
{
  "format": "boris-rendered-search-index",
  "schema_version": 1,
  "documents": [
    {
      "path": "guides/building-pages.html",
      "title": "Building Pages",
      "sections": [
        {
          "level": 1,
          "heading": "Building Pages",
          "fragment": "building-pages",
          "text": "Pages are Markdown files under content/...",
          "code": ""
        }
      ]
    }
  ]
}
```

| Field | Type | Description |
|---|---|---|
| `format` | string | Always `boris-rendered-search-index` |
| `schema_version` | integer | Always `1` for this version |
| `documents[].path` | string | Output-relative path, no leading slash, ends in `.html` |
| `documents[].title` | string | Normalized page title |
| `sections[].level` | integer | `0` for pre-heading content, `1`–`6` for heading levels |
| `sections[].heading` | string | Heading text (empty for level 0) |
| `sections[].fragment` | string | The heading's `id` attribute for deep linking |
| `sections[].text` | string | Prose text (entities decoded, whitespace collapsed) |
| `sections[].code` | string | Code block content, separate from prose |

## JSON IR

```bash
./zig-out/bin/boris --out .boris
```

Schema version: `0.2.0`

Output files:

| File | Description |
|---|---|
| `manifest.json` | Build metadata, schema version, compiler id, and per-page records |
| `graph.json` | Full typed graph with parent/child edges, wiki-link edges, include edges, and reverse index |
| `build-report.json` | Build timing, page count, and diagnostic summary |

The `manifest.json` `schemaVersion` field is `"0.2.0"`. The `compiler_id` field is `"boris/0.8.1"`. Breaking changes to the IR shape increment `schemaVersion`. Product version changes may increment `compiler_id` without changing `schemaVersion`.

## RAG Corpus

```bash
./zig-out/bin/boris --rag --rag-dir rag
```

Output directory:

```text
rag/
  INDEX.md              # corpus overview and navigation guide
  UPLOAD-GUIDE.md       # instructions for uploading to a RAG provider
  catalog.jsonl         # one JSON record per page (JSONL format)
  catalog_meta.json     # corpus format, schema version, and build metadata
  system/               # curated narrative seeds (product description, architecture)
  content/pages/        # one Markdown file per published page
  graph/
    entity-catalog.md   # full entity list with metadata
    relations.md        # parent/child and relationship summary
  parts/                # present when --split-size is used
    part-1.md
    part-manifest.json
```

Each `catalog.jsonl` record:

```json
{"entity_id": "guides/building-pages", "title": "Building Pages", "path": "content/pages/guides/building-pages.md", "status": "published", "tags": ["guides", "authoring"]}
```

## AI Context Bundle

```bash
./zig-out/bin/boris --context --context-dir context
```

Output directory:

```text
context/
  bundle.md         # full site content in one Markdown document, ordered by graph
  manifest.json     # page list, build metadata, and schema version
  graph.json        # graph snapshot (same structure as IR graph.json)
  pages/            # one Markdown file per page
    index.md
    getting-started.md
    guides/
      overview.md
```

The `bundle.md` file concatenates all pages in graph order (Trunks first, then their Satellites depth-first), separated by horizontal rules and page metadata headers. It is designed to be pasted or uploaded as a single context document.

## `llms.txt`

```bash
./zig-out/bin/boris --llms --llms-path llms.txt
```

Format: plain text, UTF-8, community `llms.txt` standard.

```text
# Boris documentation

> This file is generated by Boris from a validated Trunk/Satellite content graph.

## Documentation

- [Boris Home](/index/): Product overview and quick navigation
  - [Getting Started](/getting-started/): Install and run Boris
    - [Building Pages](/guides/building-pages/): Page authoring guide
```

The file reflects the current validated graph. Indentation depth matches the Trunk/Satellite hierarchy. Each entry includes the page title (linked) and a one-line summary derived from the page's first paragraph.

## Diagnostic Troubleshooting for Output Artifacts

| Issue / Symptom | Primary Cause | Remediation Procedure |
|---|---|---|
| `search-index.json` missing | HTML compiler built site, but search index tool was not invoked | Run `zig build --build-file tools/search-index/build.zig run -- --root=./dist --out=./dist/_boris/search` |
| RAG corpus missing `parts/` | `--split-size` flag was omitted during RAG build | Pass `--split-size BYTES` (e.g. `--split-size 2000000`) to enable part chunking |
| `dist/.boris/` missing IR | Default CLI run without `--out` flag | Run `./zig-out/bin/boris --out dist/.boris` to generate JSON IR files |
| `llms.txt` missing | Default CLI run without `--llms` flag | Run `./zig-out/bin/boris --llms --llms-path dist/llms.txt` |
| `context/bundle.md` missing | Default CLI run without `--context` flag | Run `./zig-out/bin/boris --context --context-dir dist/context` |

### Output Verification Checklist

1. **HTML Site**: Verify HTML files exist under `dist/` or target directories (`dist/corporate`, `dist/minimalist`).
2. **Search Index**: Verify `dist/_boris/search/search-index.json` exists and validates with schema version 1.
3. **Machine Exports**: Confirm `dist/rag/catalog.jsonl`, `dist/.boris/manifest.json`, `dist/context/bundle.md`, and `dist/llms.txt` are populated.
