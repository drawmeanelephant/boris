## Mission

Keep `content/` a living sample site that matches the Boris v0.8.1 candidate:

1. Markdown in → validated Trunk/Satellite graph → static HTML by default.
2. Oliver (pinned Zig library, see `docs/contracts/oliver-renderer.md`) renders Markdown in-process.
3. The same compiler authorities support IR, RAG, Context, `llms.txt`, RSS,
   sitemap, rendered search, and publication evidence projections.
4. Examples are real, clickable, and safe to compile.

This is author-content work. Do not change the Zig compiler, build system,
contracts, or the Oliver pin as a documentation cleanup.

## Product truth

Read `docs/STATUS.md`, the top of `CHANGELOG.md`, `AGENTS.md`, and the relevant
normative contract before changing claims. The source frontmatter key is
`parent` only; `parentEntry` and `parent_entry` are unknown keys. The complete
current author key set is:

```text
id, title, parent, status, tags, relations, published_at, summary
```

`title` is optional. `status` is `draft`, `published`, or `archived`. A Trunk
omits `parent`; a Satellite names one direct parent. Nested finite acyclic
chains are valid. Draft pages are excluded from published projections.

The constrained product components are `<Aside>` and `<Details>` only. RAG
`:::kind` / `:::details` is export-only. Includes live under
`content/includes/`; that directory is not a page tree. Wiki-links use exact
entity ids and may include a rendered heading fragment.

## CLI truth

```text
boris build                         → HTML under dist/ by default
boris validate                      → HTML compiler preflight; writes nothing
boris watch                         → HTML build followed by file watching
boris check                         → graph/dependency health report
boris impact ID                     → transitive dependents report
boris plan --profile PATH           → normalized publication declaration
boris build --out DIR               → JSON IR
boris build --rag --rag-dir DIR     → RAG corpus
boris build --context --context-dir DIR → Context bundle
boris build --llms                  → llms.txt
boris build --rss ...               → RSS 2.0 (requires site metadata)
boris build --sitemap ...           → HTML sitemap (requires site URL)
```

`validate` is not an alias for `check`: it checks the selected HTML source and
configuration path without publishing. `check` runs after the graph is valid
and may return exit `1` for an analysis finding such as an unreferenced page.

## Authoring rules

- Keep frontmatter closed, one-line, and exact; no arbitrary YAML or comments.
- Use `parent` with exact entity ids; never use legacy parent aliases.
- Keep live includes and wiki-links pointed at real pages/fragments.
- Keep component tags outside fences, with line-start closing tags and no
  nesting.
- Keep examples of unsupported syntax in inert `text` fences, with
  `OLIVER-PENDING` or `PRODUCT-OFF` labels.
- Prefer wiki-links for internal references and verify rendered `.html` routes.
- Do not claim compiler-owned search is a separate required post-build step.
- Do not commit `dist/`, `.boris/`, `rag/`, `context/`, search caches, or proof
  reports.

## Acceptance checks

```bash
zig build
./zig-out/bin/boris validate --input content --quiet
./zig-out/bin/boris build --input content --html-dir .tmp/docs-site --quiet
test -f .tmp/docs-site/index.html
test -f .tmp/docs-site/_boris/search/search-index.json
```

The repository release gate and `zig build test` are the final authorities.
