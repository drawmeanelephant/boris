# Astro import initial-create apply (v1)

**Status:** normative developer-tool contract — Slice B1 only.

`boris-migration-lab --mode=astro-import-apply` publishes a reviewed Slice A
plan exactly once into a previously nonexistent Boris source destination:

```text
--mode=astro-import-apply --root=DIR --content-root=RELATIVE_DIR
  --project-id=ID --plan=PATH/import_plan.json --destination=NEW_DIR
```

All six values are required. The `source_snapshot.json` adjacent to `--plan` is
part of the authority, not optional metadata. Before creating a stage the tool
parses the exact v1 plan, recomputes its digest and policy digest, verifies the
adjacent snapshot digest, rebuilds Slice A's complete no-follow source snapshot
from the live root, and requires byte equality. It rejects non-null previous
manifest state, any action other than `create`, `quarantine`, or `unsupported`,
duplicate writable paths or final identities, malformed fields, changed source
bytes, symlinked selected-root components, and every existing destination.
Every candidate is rendered and passed through Boris's native parser before a
stage is created; a generated validation failure therefore cannot leave a
partial destination or a stale owned stage.

Only `create` rows write files. Their verified source-frontmatter envelope is
removed and replaced with canonical Boris frontmatter in this order: `id`,
`title`, `status`, `tags`. Body bytes, including links, asset references, code,
Unicode, and line endings, are otherwise preserved. Quarantine and unsupported
rows produce no files.

The complete tree is written in the sibling hidden stage
`DESTINATION.boris-astro-import-stage`. An unrecognized stale stage is refused;
an abandoned stage carrying the exact invocation marker is removed safely. The
stage contains generated `content/**` files and one importer-owned hidden
namespace, `.boris-astro-import/`, containing `manifest.json` and immutable
SHA-256-addressed base blobs of the exact generated bytes. The compact manifest
records source path/hash, import-record ID, Boris path, entity ID, generated
hash, base-blob hash, plan digest, and a recomputable manifest digest. No
timestamps, hosts, machine paths, asset copies, or executable content enter it.

Immediately before publication the destination is checked again, then the
sibling stage is renamed with no-replace semantics. Any earlier error removes only the stage
recognized by its exact marker; it never modifies a pre-existing destination.

Deferred: clean re-import, keep/update behavior, BASE/LOCAL/INCOMING conflicts,
moves/deletions, MDX conversion, asset relocation, route observation, and wider
Astro profiles.
