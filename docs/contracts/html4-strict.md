# HTML 4.01 Strict target profile

**Status:** normative, opt-in (`--target-profile NAME=html4-strict`)

**Modules:** `src/render.zig`, `src/html4_strict.zig`, `src/compile.zig`,
`src/publication_proof_pack.zig`

**Related:** [HTML output](html-output.md), [Oliver](oliver-renderer.md),
[diagnostics](diagnostics.md), [heading IDs](heading-ids.md)

## Conformance boundary

The selected target's **complete generated HTML documents** are checked, not
only Oliver fragments: selected author/theme layout bytes, `{{content}}`,
generated navigation, breadcrumb, children, TOC, metadata, relations,
backlinks, Aside and Details, plus the compiler-owned Proof Pack
`_boris/proof/index.html`. The target uses the exact HTML 4.01 Strict public
DOCTYPE and UTF-8; Boris never silently rewrites author layouts or raw HTML.
The default HTML and opt-in XHTML paths retain their prior output bytes.

The [compatibility theme](../../themes/html4-strict/) supplies a working full
document and stylesheet:

```sh
boris build --theme themes/html4-strict --target-profile default=html4-strict
boris validate --theme themes/html4-strict --target-profile default=html4-strict
```

Other layouts, including `--layout-rule` selections, can opt in if their
*assembled output* passes the same gate. The default HTML5 theme does not
qualify. No `.html`, `.htm` or `.xhtml` theme, content-local, or static
passthrough asset (case-insensitive extension) is permitted on this target:
those files bypass the renderer/layout path and
would otherwise remain unchecked. CSS, images and non-HTML assets are copied
as usual. The private `watch --serve` helper UI is generated by the preview
server and is **not** a target file.

## Validation method and limits

Before writing each page to staging, and during zero-write `validate`, Boris
checks the *exact assembled bytes*. It requires the Strict DOCTYPE, one
`html` with `head` (exactly one title) before `body`, UTF-8, balanced tags,
closed attribute vocabulary with quoted values, entity and ID syntax, unique
IDs across the entire document, HTML 4.01-compatible containment for accepted
elements, and nonempty list/table sections. Unsupported elements, attributes,
entities, comments, processing instructions, or unchecked raw HTML are errors.
It checks compiler-owned proof HTML before installing that report. Page
validation failures prevent the staged target from committing; a proof
generation failure after target commit retains the previously committed
proof pair and reports a publication-evidence failure, as with other proof
errors.

This is a **conservative valid subset**, not an SGML DTD engine. Some otherwise
valid HTML 4.01 documents are rejected (including unlisted named entities,
arbitrary manually authored HTML and uncommon table structures). The Strict
DTD uses SGML features not accepted by XML validators such as `xmllint`.
The end-to-end fixture checks a representative complete site including proof
HTML, and an independent HTML 4-aware `tidy -utf8 -qe` run can corroborate
sample output. Neither the Oliver fragment serializer nor Boris claims
universal DTD certification of arbitrary input or accessibility conformance.
`validate` does not generate or preflight the proof page because it makes no
publication reports; `build` checks it before its pair is installed.

## Authoring tradeoffs

Oliver rejects verbatim raw HTML, non-1 ordered-list starts, invalid and
duplicate heading IDs, and empty tables. This restriction applies only to
strict targets; the [general heading-ID contract](heading-ids.md) still allows
duplicate headings on ordinary HTML and XHTML targets. The final checker also
catches collisions **between** Oliver segments, Aside IDs, generated chrome,
and the layout. A failure produces `EHTML4STRICT` with page, source and
selected-layout context and exits as a content error (`1`); `--quiet` does not
hide it, and `--report` includes it.

Strict chrome replaces HTML5 `nav`/`section`/`aside`/`details` with classed
`div` (and Details summary with visible `p`), omits ARIA/data attributes and
native disclosure behavior, and keeps link text and classes. Oliver's
footnotes likewise lose HTML5 wrappers and data markers, and Cooklang output
loses machine-readable `data-*` quantities/references (see Oliver's
upstream profile documentation). The source graph, IR, other targets,
and author files do not change. Treat strict as a compatibility format,
not a better default for modern sites.
