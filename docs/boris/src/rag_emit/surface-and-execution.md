# `src/rag_emit.zig` surface and execution

## Public API surface

### Types

**`CatalogEntry`** — a flat, fully-owned struct representing one row of the RAG catalog. All fields are `[]const u8`. The field order is normative: `rag_id`, `rag_path`, `category`, `title`, `entity_id`, `role`, `parent_entry`, `tags`. Optional fields default to `""` (empty slice). This order is the stable schema documented in the `INDEX.md` footer generated by `renderIndex`.

**`Stats`** — aggregated count struct passed to `renderIndex`. Fields: `system_docs`, `content_pages`, `graph_docs`, `catalog_entries` (all `usize`).

## Behavioral contracts and invariants

### H1 normalization

Two private functions enforce the H1 rules described in the `renderIndex` footer comment:

**`stripLeadingAtxH1(body)`** — scans forward through lines, skipping blank lines, and removes the first non-blank line if and only if it is an ATX `#` H1 (single `#` followed by space, tab, or end-of-line). CRLF is handled: trailing `\r` is stripped before the ATX check. Returns a sub-slice of the input; no allocation occurs. If the first non-blank line is not H1, the full body slice is returned unchanged.

**`demoteAtxH1ToH2(body, allocator)`** — rewrites every ATX H1 (`# `) in the body to H2 (`## `) by prepending one additional `#` character. The left-whitespace indent of the line is preserved; only `left[^1_0]` (the `#` char of an H1) triggers the promotion. CRLF is preserved. Allocates a new buffer; the caller owns the result. `errdefer` protects the buffer on allocation failure.

**`renderBody(segments, allocator)`** iterates `[]const aside.Segment`. For markdown segments that are non-blank (after trim), it pipes through `stripLeadingAtxH1` then `demoteAtxH1ToH2`. Blank markdown segments are passed through verbatim (whitespace preservation). Aside and details segments are serialized via `aside.formatRagDirective` / `aside.formatDetailsRagDirective` respectively.

**Claim boundary**: The stripping and demotion are structurally guaranteed for any input passed through `renderBody`; they are not conditional on upstream validation. The correctness of the ATX H1 detection (`isAtxH1Line`) is directly testable by the inline logic but has no dedicated unit test in this file—it is covered only transitively through `renderContentDocument`.

### Catalog JSONL serialization

`renderCatalogJsonl` constructs each JSON object line by hand using explicit `appendSlice` calls and `json_out.escapeAppend` for every string value. Key order is fixed and matches `CatalogEntry` field declaration order. The function does not use `std.json` for serialization, so key order cannot drift due to struct tag changes or comptime ordering.

`json_out.escapeAppend` (confirmed from `src/json_out.zig`) handles: `"` → `\"`, `\` → `\\`, `\n` → `\n`, `\r` → `\r`, `\t` → `\t`, and control characters below 0x20 as `\uXXXX`. Non-ASCII bytes above 0x20 pass through as-is (no UTF-8 validation or Unicode escape normalization). This is adequate for well-formed UTF-8 input but does not catch invalid UTF-8 sequences—that responsibility lies upstream.

The embedded test `"catalog JSONL field order and escaping are stable"` directly verifies the serialized output byte-for-byte for a `CatalogEntry` whose `title` contains `"` and `\n`. This is the strongest evidence of correctness available in the file.

### Relations document ordering

`renderRelations` builds the machine-friendly edge list by iterating `pages` for satellites with non-null parents, collecting `{src, tgt}` pairs, then sorting them lexicographically by `src` then `tgt` using `std.mem.sort`. Trunk-hub sections iterate `pages` in input order (expected to be post-freeze id-sorted order from the caller). The contract comment in the function body states: "Hubs and satellite lists are ordered by `entity_id`. Edge list is ordered by source id then target id." This ordering is enforced mechanically by the sort; hub section order depends on the caller having passed a freeze-sorted slice.

### Allocator ownership

Every function that allocates uses a named `gpa` parameter for the returned `[]u8` and `errdefer doc.deinit(gpa)` to release intermediate `ArrayList` storage on error. The dual-allocator pattern in `renderContentDocument` (`gpa` for the final output, `scratch` for body and intermediate strings) is structurally correct in the sense that `errdefer doc.deinit(gpa)` protects the output list, and the `related` ArrayList is `defer related.deinit(scratch)`. However, the `body` and `tags` intermediates allocated from `scratch` are not individually deferred—they are expected to be freed when the scratch arena is torn down by the caller. This is a common and intentional pattern for arena-backed scratch allocators but imposes a constraint on the caller: `scratch` must be an arena or the caller must accept a small intermediate leak on non-error paths.

**Claim boundary**: The scratch-allocator intermediates not being freed individually is not a defect if `scratch` is an arena, which is the documented and idiomatic use. It becomes a leak if `scratch` is a GPA. No test in this file validates that constraint.

## H1 normalization detail

The `isAtxH1Line` predicate accepts:

- `"#"` (lone hash, length 1)
- `"# "` (hash-space)
- `"#\t"` (hash-tab)

It rejects:

- `"##"` (H2 or deeper — `left_trimmed[^1_1] == '#'`)
- Any line not starting with `#`

The function operates on the **left-trimmed** line, not the raw line. Leading spaces/tabs are stripped by the caller before passing to `isAtxH1Line`. This means an indented `#` heading (`   # Title`) is recognized as H1 for stripping/demotion purposes, which is consistent with CommonMark (up to 3 spaces of indent is a valid ATX heading).

`demoteAtxH1ToH2` preserves the original leading whitespace by slicing `line[0 .. line.len - left.len]` and prepending it before the added `#`. The re-emit is: `{leading_ws}#{original_H1_line}`, resulting in `{leading_ws}## Title` for an original `{leading_ws}# Title`.

**Residual gap**: there is no test covering indented H1 demoting, H1-only-body behavior (body = `"# Title\n"`), or a body whose first non-blank line is `"#"` (lone-hash). These are exercised only if the integration test suite sends such inputs through `renderContentDocument`.
