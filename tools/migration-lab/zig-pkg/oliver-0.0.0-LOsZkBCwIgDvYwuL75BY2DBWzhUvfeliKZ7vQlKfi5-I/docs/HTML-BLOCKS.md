# Markdown HTML blocks (§4.6)

**Status: complete — all seven types implemented (types 1–5 plus 6/7).**
Scorecard: 44/44.

This document is the contract for Oliver's HTML block handling, derived
from the CommonMark 0.31.2 spec prose and examples plus the raw-HTML
policy already recorded in docs/RAW-HTML.md.

## 1. What the spec says

§4.6 defines seven start conditions. A block begins with a line that
matches one of them; the block ends per type:

- **Type 1:** `<script`, `<pre`, `<style`, or `<textarea` (case-insensitive),
  followed by whitespace, `>`, or `/>`. Ends at the matching closing tag
  (`</script>` etc.) or a blank line.
- **Type 2:** `<!--` comment. Ends at `-->`.
- **Type 3:** `<?` processing instruction. Ends at `?>`.
- **Type 4:** `<!` + ASCII letter declaration. Ends at `>`.
- **Type 5:** `<![CDATA[`. Ends at `]]>`.
- **Type 6:** `<` or `</` + a block tag name + whitespace, `>`, or `/>`
  (the 62-element HTML block-tag list). Ends at a blank line.
- **Type 7:** the entire line (after ≤3 spaces of indentation) is a
  complete open tag or closing tag followed only by spaces/tabs/form
  feeds. Ends at a blank line.

Two properties shape the design:

- **Interruption:** "All types of HTML blocks except type 7 may interrupt
  a paragraph." So type 7 cannot interrupt; types 1–6 can.
- **Content is verbatim:** an HTML block's source lines are included
  without escaping and without inline parsing; leading spaces are
  preserved (only container prefixes are stripped).

The raw-HTML policy is already decided (docs/RAW-HTML.md §3): Oliver
renders raw HTML verbatim (CommonMark's *allowed* behavior), so HTML
blocks are a block-level rendering of the same policy.

## 2. Implementation

An HTML block is an **open leaf** in the block pass, modeled exactly like
`IndentedCode` (`src/markdown.zig` `HtmlBlock`), carrying the start
type so the end condition is per-type:

- **Start detection** (`tryHtmlBlockStart`) runs in the main loop where
  other block starts are tried, after container markers are stripped. It
  skips up to three columns of indentation, requires `<`, then tries:
  1. **Type 1:** `<script`, `<pre`, `<style`, or `<textarea`
     (case-insensitive) followed by whitespace, `>`, or `/>`.
  2. **Type 2:** `<!--`.
  3. **Type 3:** `<?`.
  4. **Type 4:** `<!` + an ASCII letter.
  5. **Type 5:** `<![CDATA[`.
  6. **Type 6:** `<`/`</` + one of the 62 `html_block_tags` + space, tab,
     VT, FF, `>`, `/>`, or EOL (cmark's `blocktagname` scanner shape; the
     name match is case-sensitive, matching the reference implementation
     the corpus is generated by — uppercase `<DIV>` routes through the
     type-7 scanner instead).
  7. **Type 7** (only when no paragraph is open — it cannot interrupt):
     the rest of the line is a complete §6.6 open tag or closing tag
     (the shared `scanHtmlTag`) followed only by spaces/tabs/form feeds.
     Comments/PIs/declarations/CDATA never match (the tag grammar
     excludes `<!`/`<?`).
- **Content accumulation:** each line's container-stripped remainder is
  appended verbatim, leading spaces and line-ending bytes included —
  source lines are not contiguous once container prefixes are stripped,
  so the payload is arena-owned (cmark's `add_line` semantics).
- **End condition:** types 1–5 end at the first line containing their
  terminator (`</script>`/`</pre>`/`</style>`/`</textarea>`, `-->`,
  `?>`, `>`, `]]>`) — the terminator may sit on the start line itself,
  closing the block after exactly one line. Types 6/7 end at a blank
  line. A blank line also closes a type 1–5 block (the spec's
  conservative fallback); the containing block/document boundary closes
  it too (container-depth tracking).
- **Model/renderer:** a leaf block tag `.html_block` with
  `data.html_block` = the verbatim arena payload (src/document.zig). The
  renderer writes it without escaping and appends exactly one `\n` if the
  payload does not end with one (cmark's `cr()`), matching the reference
  output for unterminated final lines.

Because type 7 cannot interrupt, an open paragraph absorbs a would-be
type-7 line as continuation text (`*foo*` then `<b>bar</b>` stays one
paragraph, per spec example 177). Types 1–6 can interrupt — a paragraph
ends when one of their start lines arrives, which is what lets a `<!--`
comment split a list into two (`-   foo` … `<!-- -->` … `-   bar`, spec
examples 308–309).

## 3. Chosen behaviors and recorded divergences

1. **All seven types implemented.** `--section "HTML blocks"` scores
   44/44, and the §4.6 family is fully conformant. (With the §4.7
   angle-destination edge case #201 closed by the full-conformance
   milestone, the entire 652-example corpus is green.)
2. **Type-6 tag names are case-sensitive** (lowercase list), matching the
   reference implementation that generates the corpus; the spec's
   "case-insensitive" prose is satisfied in effect because uppercase tags
   take the type-7 path (a `<DIV>` line is a complete tag on its own
   line). Type 1's four element names are matched case-insensitively, as
   the spec requires.
3. **The 62-element block-tag list** is the HTML5 list from the spec,
   including `search` (a 2022 addition to the spec's own table).
4. **Content is never re-escaped or parsed** — the block's bytes render
   verbatim per the raw-HTML policy. A `&` or `*` inside the block is
   nothing but its literal byte.
5. **A blank line ends the block even inside a container** — matching the
   leaf model: the blank closes the block, and a markerless blank closes
   the containing quote/item too (per the container rules).
6. **Type-1 terminators are not validated beyond the tag name** — a
   `</script>` anywhere on the line ends the block, whether or not the
   line's remainder parses as a complete closing tag. This matches the
   spec's literal end-condition wording.

2. Fixtures: `html-block-type1` through `html-block-type5` (each start
   kind, multi-line, with and without the terminator on the start line),
   `html-block-type1-raw` (type-1 content stays verbatim: no entity
