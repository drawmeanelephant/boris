## Architecture chosen

Single-pass line-based block parsing per frontend, then inline parsing
(block-then-inline matches the CommonMark precedence model). Both frontends
build the same arena-backed `Document`; one renderer consumes it. Node text
payloads are borrowed slices of the input. Rendering walks the tree with an
explicit stack. Offsets are u32 with a documented 4 GiB input bound.

Module names track the mission's suggestions (`source`, `document`,
`markdown`, `textile`, `html`, `diagnostic`) — `span` lives inside
`source.zig`; `node` inside `document.zig`, since each pair is one cohesive
concept.

## Public API shape (provisional)

```zig
const result = try oliver.parse(allocator, source, .markdown, .{});
defer result.deinit();
try oliver.html.render(allocator, &writer, &result.document, .{});
```

`ParseResult { document, diagnostics }`; `Dialect { markdown, textile }`;
`ParseOptions` (empty); `ParseError { InputTooLarge, OutOfMemory }`. The
renderer takes a pointer to any `writeAll`-capable writer (Zig 0.16
`std.Io.Writer` values), so it streams to memory or a file without reparsing.

## Memory ownership model

Caller supplies the allocator. `Document` owns an `ArenaAllocator`; all nodes
and diagnostics live in it; `deinit()` frees everything at once. Text is
borrowed from the input (must outlive the result) — never copied. The
renderer allocates only a temporary traversal stack. No globals, no caches.

## Addendum: code spans (session 3)

- **Implemented §6.6** on the same scan → match → emit seam. Backtick-string
  discovery runs ahead of delimiter scanning (per-line, but spans may cross
  lines), so code span content is opaque to `*`/`_` before flanking is
  classified — the delimiter-opacity precedence from §6.1's "code spans have
  higher precedence than any other inline constructs."
- **Run-length matching:** an opener closes at the next backtick string of
  equal length; `2-against-1` does not match, longer content runs are kept,

  one arena-owned payload (normalized copy — the only inline whose content
  is not a borrowed source slice), and the node span covers the whole
  construct including backticks. Renderer escapes content as text

## Addendum: inline links (session 4)

- **Implemented §6.6 (inline links)** on the same scan → match → emit seam
  as a second discovery pass with its own bracket stack. Unescaped `[`/`]`
  become scan items; on a `]` whose nearest `[` is followed by a valid
  `(...)` in the source, the bracket range plus the consumed `(...)` items
  splice into a single `link` item (children = link-text items), and every
  earlier `[` dies — links cannot contain links, innermost wins (the spec's
  bracket-stack algorithm, §Appendix). Brackets that never form a link stay
  literal text. Link text is matched as a **fresh inline scope** (the
  spec's "process emphasis with the `[` opener as stack_bottom"): emphasis
  and code spans inside link text work; delimiters outside never reach in.
- **Precedence verified:** `*[foo*](/uri)` is a link (brackets bind tighter
  than emphasis), `` [foo`](/uri)` `` keeps the code span (code spans bind
  tighter than brackets), `[foo [bar](/uri)](/uri)` leaves the outer
  brackets literal, `[link [foo [bar]]](/uri)` keeps balanced inner
  brackets as text. Verified byte-for-byte against spec examples 482–536
  (inline subset), including the dest/title forms (`<...>`, bare with
  balanced/escaped parens, `"`/`'`/`(...)` titles, one-line-ending
  separators, no line endings inside destinations, multiline titles).
- **Model/renderer:** `data.link` is arena-owned `{ href, title }` with
  backslash escapes resolved at parse time (the renderer never resolves
  dialect escapes). The renderer percent-encodes `href` per a documented
  policy derived from spec examples (encode everything except alphanumerics
  and `-_.~!*'(),;:&=+$#@/%?`), then HTML-escapes; `title` is
  HTML-escaped without percent-encoding; attributes emit in fixed order
  `href` then `title`. `![alt](url)` currently parses as `!` + link
  (images deferred — documented divergence).
- **DoS guards:** the smoke test caught a quadratic blowup on `[a](`
  repeated (every `]` rescanned the rest of the line). Fixed with a paren
  depth cap of 32 — explicitly sanctioned by the spec ("implementations may
  impose limits on parentheses nesting... at least three levels should be
  supported") — and a 2048-byte per-component scan cap. Stress shapes now
  complete in ~0.02–0.2 s (were ~4 s).
- 22 new Markdown fixtures (74 Markdown total; one of them locks the
  entity divergence — `&ouml;` stays literal in destinations/titles until
  the entity milestone), 11 new unit tests, 1 renderer-only link test.
  Tests: 53/53; `zig fmt --check` clean; build clean.
- Next slice: reference links (§4.7 link reference definitions, needed for
  `[text][label]` and `[text][]` forms) or images (§6.7) or Textile inline
  mapping onto the same seam.

## Addendum: reference links (session 6)

- **Two-phase restructure.** Link reference definitions (§4.7) must be
  known before inline parsing (a use may precede its definition), so
  `parse` now runs the block pass to completion collecting definitions
  (into a case-insensitive map) and *deferring* inline parsing, then
  resolves inlines in phase two with the definitions map in hand.
  Definitions are extracted at paragraph close: the first line must be
  `[` + label + `]` + optional spaces/tabs + destination; a title may
  follow on the same line (spaces/tabs separated) or on the *next* line;
  nothing else may follow a title on its line — a failed title attempt
  ends the definition at the destination's line (spec example
  `[foo]: /url
"title" ok` is definition + paragraph). A paragraph whose
  content is entirely definitions renders nothing; a definition inside a
  paragraph of real content is consumed without affecting the rest.
- **Label matching (§6.3):** labels are normalized by Unicode full
  case-fold plus whitespace collapse. The case-fold tables (single
  codepoints + the 104 multi-codepoint expansions, e.g. `ẞ` → `ss`) are
  generated by `tools/gen-unicode.py` from the Unicode standard
  (`str.casefold`, Unicode 13.0.0 — the same data the spec references)
  into `src/unicode.zig`; `foldInto` binary-searches then expands.
  First definition wins; an unclosed `[` can never be a definition;
  definitions cannot interrupt paragraphs (they must be a continuation
  of content or start at a blank-line boundary).
- **Reference forms (§6.6):** at each `]` in discovery, after a failed
  inline `(...)`, resolution tries full `[text][label]` then collapsed
  `[text][]` then shortcut `[text]` (the label is the link text itself),
  each via the definitions map. Per spec example 561, a `(` after the `]`
  that fails to parse as an inline destination does *not* block the
  shortcut form. Reference labels cannot contain other reference links
  (the label is matched raw from the source, not as inlines).
  Reference links produce the same `link` node as inline links — no
  model or renderer change.
- **Verified** byte-for-byte against the §4.7 and §6.6 reference-link
  examples (full/collapsed/shortcut, Unicode and case-insensitive
  labels, whitespace normalization, first-wins, use-before-definition,
  multiline titles, cannot-interrupt, escaped labels, and the
  `[foo](not a link)` fall-through), plus 24 new Markdown fixtures.
- **Smoke additions:** 50k shortcut label bombs, 50k near-miss labels
  (differ by one character), 30k collapsed forms, 20k failed-inline
  fall-throughs, a 20k-definition storm with interleaved uses, and a
  200 KB label against the definitions map — all linear, suite still
  runs in well under a second.
- 115 Markdown fixtures (24 new on top of the images milestone's 91),
  62 library tests, 68/68 total; `zig fmt --check` clean; build clean.

## Addendum: autolinks (session 8)

- **Implemented §6.8 (autolinks)** on the same scan → match → emit seam,
  per the design contract docs/AUTOLINKS.md (written from the spec and
  committed before any autolink code). A `<` is a recognizer in the
  scan: URI autolinks (scheme 2–32 chars followed by `:`, then content
  up to the first `>`; content forbids ASCII control, space, and `<`)
  and email autolinks (the non-normative HTML5 email regex, anchored),
  tried in that order. Recognition runs ahead of bracket discovery, so
  an autolink swallows what looks like link syntax (spec example 526:
  `<https://example.com/?search=](uri)>` keeps `](uri)` in its href),
  and code spans bind more tightly than `<` as before.
- **Model/renderer:** `.autolink` joined the leaf inlines — `data.autolink
  = { href, label }` — and DOCUMENT-MODEL invariants 4/5/8 were updated
  (it is the first leaf inline whose payload is *not* escape-resolved:
  backslash escapes are inert inside autolinks, so the label is the raw
  content verbatim, unlike `data.link`; the `mailto:` prefix makes the
  href an arena copy rather than a source slice). The renderer emits
  `<a href="...">label</a>`: href percent-encoded under the shared link
  policy (`&` → `&amp;`, `\` → `%5C`, `[` → `%5B`), label HTML-escaped
  like text.
- **One bug found during verification:** the content span initially
  excluded the scheme (the href/label must be the *whole* text between
  the angle brackets — `<m:abc>` fails only because the scheme is 1
  char, not because schemes are omitted from content). Fixed to span
  from after `<` to the `>`, inclusive of scheme and colon.
- **Verified** byte-for-byte against all 19 §6.8 spec examples 567–585
  via the spec-conformance harness (Autolinks 8/19 → 19/19), and the
  scorecard moved 360/652 → 377/652 overall with no regressions — the

  lists, tight/loose) is specified, but only §5.1 ships here.
- **The container stack.** Phase 1 now keeps a stack of open containers
  plus one open leaf, replacing the flat single-paragraph loop: each line
  matches containers top-down consuming one `>` marker each (≤3 leading
  spaces, one following space), a blank line closes the leaf and any
  container whose marker was absent, a lazy continuation keeps unmatched
  containers open when the remainder is paragraph continuation text,
  and new block starts (block quote, ATX heading) interrupt the open
  paragraph. Definitions and deferred inlines are unchanged — phase-2
  jobs already carry their node, and definitions stay document-global.
- **Block quote semantics landed:** nesting (`> > foo`), laziness
  (including omitting any number of initial `>`s on nested continuation

  interruption (`foo\n> bar`), empty quotes (`>`), and definitions

## Architectural concerns discovered

1. **Zig 0.16's I/O redesign.** `std.io.AnyWriter` is gone; writers are
   vtable structs under `std.Io`, and `main()` now takes `std.process.Init`.
   The renderer's `anytype`-writer seam absorbed this cleanly, but any C-ABI
   or doc example must target the 0.16 shapes. The render-to-buffer path for
   the future C ABI should use `std.Io.Writer.Allocating`.
2. **The inline milestone will restructure `parseInlines`.** The slice's
   inline seam is a single text node per range; the delimiter algorithm will
   replace it. Block structure (the `Paragraph`/`AtxHeading` code) is
   expected to survive mostly intact, which is why the block layer was worth
   building first.
3. **Trailing-space policy must be decided before hard breaks.** Markdown
   hard breaks depend on trailing spaces, which the slice currently trims.
   The fixture `escape-special` and unit tests pin current behavior; the
   inline milestone must change trimming deliberately, with new fixtures.
4. **Textile `p.`/`hN.` content is preserved verbatim** while Markdown
   trims — a genuine dialect difference, now pinned by fixtures
   (`p-prefix`, `heading`), that must survive the inline milestone.
