# repro/420 — Touch Atlas streaming checks parse is byte-offset sensitive

Standalone reproducer for **drawmeanelephant/boris#420** (and the investigation
recorded in **#417**). It compiles the checked-out boris `src/` (via the `src`
symlink below) — any revision carrying the bug. Verified at `30805ab8` (the
merged #409 tip, which shipped it) and the `afterparty` tip at filing time.

No oliver content, no site tree: the harness *synthesizes* a schema-valid
216-finding `checks.json`, pads it so that finding #207's `"owner"` value
straddles a 64 KiB chunk boundary, and drives the **real** `parseChecksStream`
through the exact 64 KiB streaming reader `writeAfterClaims` uses.

## Result

```
RESULT: REPRODUCED — a N-byte checks report dies at finding #207;
        the identical report at N+13 bytes parses all 216 findings.
```

## Mechanism (root cause)

1. `writeAfterClaims` streams the committed checks report through
   `EvidenceInput.pass2_buffer` — a fixed `[64 * 1024]u8` chunk — and hands the
   resulting `std.Io.Reader` to `std.json.Reader` (`src/publication_touches.zig`,
   `rewindForParse` → `parseChecksStream`).
2. The JSON scanner can only complete a string token when it fits inside the
   current 64 KiB chunk. A string **value** that straddles a chunk boundary is
   surfaced as a `.partial_string` token (`std/json/Scanner.zig`).
3. `skipJsonValue` (boris) reads exactly one token and treats it as the whole
   value. `.partial_string` falls through its `else` arm, so it returns with
   the scanner **mid-string**.
4. The next key read consumes the remainder of the string as a key token
   (`"publication"` → `"ication"`), which no finding key matches →
   `error.InvalidChecksReport`.

Whether any token straddles a boundary is a pure function of the file's byte
length — hence the byte-offset sensitivity: a 218-byte-shorter report (the
`public` target form) dies; the identical content at `default` target parses
(#417). Inside an *object* skip the depth loop reads on, so `.partial_string`
is harmless there — that is why only bare-string values skipped via
`skipJsonValue` (e.g. a finding's `domain` / `confidence` / `owner`) trigger
it, and why the `"path"` key that straddles the first boundary in the real
failing report does not.

## Files

| file | purpose |

## How to run

```sh
# from this directory (or ./run.sh)
zig build
./zig-out/bin/repro-420
```

Requires Zig 0.16.0 and a warm `~/.cache/zig` (the `oliver_cooklang` pin is
fetched by the root build; the archive is content-hashed and reused).

The reported finding #207 and the straddling byte are computed from the
generated bytes (the 208th `"owner":"publication"` occurrence), not hard-coded.

## Verifying against the original failure

The original failing report (`--target public=dist`, oliver tree, id-less
widget `<h2>`s) is byte-identical to the passing `default`-target report modulo
the target string — 136383 bytes vs 136601. The boundary analysis on the real
files found exactly two straddling tokens in the failing form:

| byte | token | context | effect |
|---|---|---|---|
| 65536 | `"path"` (key) | inside a skipped `output_location` object | harmless (depth loop) |
| 131072 | `"publication"` (value) | finding #207's `owner` | **dies at finding #207** |

The synthesized report reproduces the second row in isolation with a single
64 KiB boundary, making the failure unambiguous.
